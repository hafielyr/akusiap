| D-29 | Where shared test code lives and how tests share the database (F-05) | A fourth test project, `tests/Akusiap.TestSupport` (class library), referenced by IntegrationTests and E2E. It holds `TestDatabase` (create/migrate/drop a uniquely named DB, dropped even when setup fails), `PostgresFixture` (one migrated DB per test run, shared through the `UsesDatabase` xUnit collection), `AppFactory` (WebApplicationFactory with `TestClock` and `FakeEmailSender`; one per test so clock and inbox are never shared) and `TestData` builders that generate unique names. Browsers are installed by `tools/playwright-install.(sh\|ps1)`, which works with Windows PowerShell 5.1 when PowerShell 7 is absent | Assumed |
| D-30 | How the database is created and seeded (F-07) | EF migrations are the only way the app database is built. `schema.sql` is the design reference and must never be executed against an app database: the Neon dev database had been built from it, could not be migrated, and was reset with the owner's approval (2026-10-19; it held only the 8 `schema.sql` seed rows). `Database:MigrateOnStartup` is on in Development only; production migrates during deploy (OPS-02). The seeder (`Seed:OnStartup`, default on in every environment) is insert-only and idempotent: roles, plans and the default preset from the `schema.sql` seed, and an admin from `Seed:AdminEmail`/`Seed:AdminPassword` when both are set (a warning is logged otherwise). Sample content is seeded in Development only. Tests turn both startup steps off and call `DataSeeder` directly. Identity is registered with `AddIdentityCore<User>().AddRoles<Role>()` (unique email); cookie sign-in and password rules come with AC-01, so until then the admin is checked with `UserManager.CheckPasswordAsync` | Assumed |
| D-31 | Sign-in system and account pages (AC-01) | **Owner decision (2026-10-19):** ASP.NET Core Identity with accounts in our own database; no hosted auth service such as Clerk (paid, JavaScript-first, keeps personal data with a third party, and would need user syncing). Google sign-in is added as AC-03 once the owner creates a Google OAuth client. Account pages are hand-written Razor Pages in `Areas/Account` at `/akun/daftar`, `/akun/masuk` and `/akun/keluar` (POST only), not the Bootstrap/English Identity UI scaffold. Passwords: at least 8 characters, no character-class rules; lockout for 15 minutes after 5 failures. `AppSignInManager.CanSignInAsync` blocks deactivated users, and the page says "Akun dinonaktifkan" only after the right password, so it never reveals account state. The display name is a cookie claim (AC-04 must call `RefreshSignInAsync` after a change). Sign-in sets the culture cookie from `User.PreferredLanguage`. `/ujian` is a placeholder until CAT-01. USR-03 must call `UpdateSecurityStampAsync` when deactivating, so existing cookies stop working within the 30-minute validation interval | Decided |
| D-32 | Shape of the entitlement decision (ENT-01) | `Evaluate` also takes the share token (rule 4 needs it). `AccessDecision` adds `AccessReason` (Admin, Owner, OwnerTakenDown, TakenDown, SharedLink, NotPublished, FreeExam, RegisterToUnlock, Purchased, Subscription, TrialAvailable, NoAccess), `RequiresGuestName` (shared access for a guest) and `CanStart` (false for None and for an owner's taken-down exam). `QuestionScope` gains `None` for no access. Share tokens match exactly (case-sensitive) in constant time. Purchases and subscriptions count only when Active and their end time is strictly after now. Note for ADM-T6/OWN-04: because rule 6 comes before ownership checks for others, a Published learner or teacher exam marked IsFree would open to every registered user, so own exams must stay out of Published unless that is intended | Assumed |
| D-33 | CI shape and deployment notes (F-08) | One GitHub Actions job on `ubuntu-24.04`: restore, `build -warnaserror`, a check that the committed Tailwind CSS matches a fresh build, Playwright install with OS dependencies, then `dotnet test` for all three projects against a `postgres:17` service container via `ConnectionStrings__Test` (no secrets, never Neon). TRX results are always uploaded; Playwright traces (recorded per test when `PLAYWRIGHT_TRACES_DIR` is set) are uploaded only when the job fails. Read-only token, concurrency cancels superseded runs, and actions are pinned to major tags. Tool scripts are invoked through `bash`, so a missing executable bit can't break CI. `docs/deployment.md` recommends a Cloudflare origin certificate in Caddy (instead of Let's Encrypt behind the Cloudflare proxy) and lists app changes OPS-02 must make: persisted data-protection keys, forwarded headers, the production email sender, a protected Hangfire dashboard and structured logging. OPS-02 confirms or replaces these | Assumed |
| D-34 | How access rules and error pages are wired (AC-06) | Policies `AdminOnly` (signed in and Admin role) and `SignedIn`, applied per area folder: `/admin` → AdminOnly, `/learn` → SignedIn (a Learn page may opt out with `[AllowAnonymous]`). Guests are redirected to `/akun/masuk?ReturnUrl=…`; signed-in users without access get a real 403 rather than a redirect. Empty 4xx/5xx responses are re-executed through `/status/{code}` (before localization, so they follow the visitor's language): Indonesian/English pages for 403 and 404 and a generic one for other codes; opening `/status/…` directly is treated as 404. A lowest-priority `MapFallback` answers 404 for every method, because the static-asset catch-all route (GET/HEAD only) otherwise turns a POST to an unknown address into 405. `/admin` and `/learn` are placeholders until ADM-T1 and the learner pages. There is no "Admin" link in the header yet (no room at 360px next to the name); ADM-T1 adds admin navigation | Assumed |
| D-35 | Use-case pattern and admin content rules (ADM-T1) | Handlers live in `Application/<Feature>/<UseCase>.cs` and return `Result<T>` with `Problem`s whose `Code` is a SharedResource key (args may be keys too, such as field labels); pages translate them with `ModelState.AddProblems`. The rules are the single source of validation (no DataAnnotations on admin forms), and Application handlers are registered by `AddApplication()`. Subject names are unique ignoring case; topic names are unique within their subject, ignoring case (checked with SQL `lower()`; the unique index catches races). Names are trimmed and at most 200 characters; descriptions are optional, at most 1000. A topic can be moved to another subject. A topic used by questions can't be deleted; a subject can't be deleted while it has topics or exams; the page explains why. Deleting needs a second tap ("Ya, hapus") instead of a browser dialog. URLs: `/admin/subjek`, `/admin/subjek/baru`, `/admin/subjek/{id}` (edit, topics, add topic), `/admin/topik/{id}`. Admins see an "Admin" link in the header; below the `sm` breakpoint it replaces their name | Assumed |
| D-36 | Question editor rules (ADM-T2) | `QuestionValidator` (Application) is the single set of rules: topic, type and status required; text and explanation required (max 4000); key fact optional (max 200), hint (1000), source note (500); difficulty empty or 1–5; every option needs text (max 1000) and options must differ ignoring case; SingleChoice 2–6 options with exactly 1 correct, MultiSelect 2–8 with at least 1, TrueFalse exactly "Benar" then "Salah" with 1 correct. Drafts follow the same rules. Saving keeps the question id and the ids of kept options (matched by the posted option id), so past attempts keep pointing at the same rows; an option that past answers selected cannot be removed (retire the question and write a new one). There is no delete: Retired is the end state. Retired questions stay in exams and attempts; leaving them out of new attempts is done where questions are selected (ENT-02 `ExamQuestionScope` and SES-01 use Active only). The admin list shows app questions only (no owner), newest change first, 20 per page, filters in the query string (`subjek`, `topik`, `status`, `jenis`, `q`, `hal`). The option editor is an Alpine component in `wwwroot/js/question-form.js`, loaded as a plain script inside the page so it exists before Alpine starts | Assumed |
| D-37 | Exam editor rules (ADM-T3) | App exams only (`OwnerKind = App`, no owner). A new exam is always Draft; saving never changes the status (publishing is ADM-T6). Paid exams need a price above 0 (max Rp100.000.000) and access days above 0 (max 3650); a free exam stores no price or access days. Own-question allowance 0–10000; title required (max 200), description optional (max 4000); subject optional; a system rule preset is required and the form preselects the default one. Admins type prices as "49000", "49.000" or "Rp49.000" (`Money.TryParseIdr`: whole rupiah only, dots only as thousand separators). Exams can be deleted only when not published and never attempted or bought; their question links are removed and the questions stay in the bank. URLs: `/admin/ujian`, `/admin/ujian/baru`, `/admin/ujian/{id}`. The editor clears model-binding errors so every message comes from `ExamValidator` | Assumed |
| D-38 | Exam question picker (ADM-T4) | The picker lives on `/admin/ujian/{id}` and is the first htmx feature: page handlers (`?handler=Search`, `AddQuestion`, `RemoveQuestion`, `MoveQuestion`, `Trial`) return only the refreshed panel (counters and list) or search results, swapped with `outerHTML`; an add also swaps the search row to "Sudah ada" out-of-band. htmx sends the antiforgery token as the `RequestVerificationToken` header from `hx-headers` on the section. Only Active app questions can be added; a duplicate add is refused (checked first, and the (exam, question) primary key catches races) and the panel says so. Positions stay 1..n after every remove or move. Draft or retired questions already in an exam stay listed with a warning. Counters: total, trial, per topic, and for paid exams the D-08 trial requirement (`TrialSetRule` in Domain, also used by ADM-T6) shown as progress, not enforced here. Search shows the 20 most recently changed matches. The picker needs JavaScript (admin only) | Assumed |
| D-39 | Rule preset editor (ADM-T5) | System presets only (no owner). Blank limits mean: untimed, all questions, unlimited attempts, no pass mark; typed limits must be whole numbers, and anything else is reported instead of silently becoming "no limit". Ranges: time limit 1–600 minutes, question count 1–1000, attempts 1–100, pass mark 0–100%. Names are unique among system presets, ignoring case. Exactly one system default: making a preset the default first clears the old default with a single UPDATE and then saves, in one transaction (`IAppDbContext.BeginTransactionAsync`), because the partial unique index allows only one default at a time. The current default cannot be switched off or deleted; another preset has to become the default first. A preset used by an exam cannot be deleted (class assignments will be counted too once that table exists). URLs: `/admin/aturan`, `/admin/aturan/baru`, `/admin/aturan/{id}` | Assumed |
